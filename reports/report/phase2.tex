\subsection{The hidden set and the proxy benchmark}
The harness describes ``13 repositories'' of which only 4 are public; the hidden set is mostly private, Google-style Python
(absl, \code{*\_test.py}). We built a \textbf{proxy benchmark of 152 verified tasks from 16 public repositories the competition does
not use} (pyglove, ml\_collections, fiddle, etils, click, flask, werkzeug, attrs, tqdm, \dots). On Prajna every task passes with the gold
patch and fails with an empty patch (152/152, 0/152). Calibration against the LB: anchor 0.327 $>$ C6a\_t5 0.268 on the proxy (3
seeds each, matches the LB order), but C8 $\approx$ anchor (0.325), so the proxy resolves large differences, not $\pm$1-task ones.
For fine-tuning we split the 16 repos 8/8: own trajectories may only come from the \emph{train half}; models trained on them are
evaluated only on the 85 \emph{eval-half} tasks.

\subsection{Infrastructure on IITB Prajna}
\begin{itemize}
\item \textbf{Migration}: 55\,GB (data, snapshots, model, Claude session) via rsync; environments rebuilt. DGX nodes (8$\times$A100-80GB,
Ubuntu) have no internet $\Rightarrow$ wheels staged on the login node and installed offline. A40/L40 nodes run Rocky 8 (glibc 2.28):
vLLM still runs because its MoE kernel import is optional and \code{cryptography} was swapped for a manylinux\_2\_28 build.
\item \textbf{Evaluation queue}: one vLLM server per GPU (TP=1, scorer flags, 32k context); every GPU slot pulls
(candidate, 19-task shard) items from a shared file queue, so A100/A40/L40 GPUs drain one priority queue without reloading.
Separate queues for LoRA candidates (\code{SERVE\_SUB}), capture runs (all LLM calls recorded for SFT) and serial timing (\code{CONC=1}).
\item \textbf{Autopilot}: a cron-supervised daemon runs a headless Claude Code (Sonnet) cycle every 2\,h with a budget cap; it harvests
results, keeps GPUs fed and maintains \code{ops/autopilot/STATE.md}. Found and fixed: a missing git identity on one DGX node leaked
harness files into patches (D18); LoRA candidates evaluated on base-only servers.
\item \textbf{Scorer-speed checks}: private Kaggle kernels on the real 4$\times$L4 stack (weekly quota of 30\,GPU-h, exhausted on 9 Oct),
and serial same-hardware time ratios on Prajna as the fallback.
\end{itemize}

\subsection{The runtime wall: why thinking does not ship (yet)}
The scorer runs tasks \textbf{serially} (\code{concurrency=1}) on 4$\times$L4: $\approx$120 tasks in 12\,h is $\approx$5.5\,min per task, and
decode at batch 1 ($\approx$35\,tok/s) is $\approx$87\% of task time, so a task can afford $\approx$10k generated tokens in total.
\begin{table}[H]\centering\small
\begin{tabular}{lrrrl}\toprule
Run (30 public tasks, serial, Kaggle 4$\times$L4) & min/task & 120 tasks & solved & \\\midrule
C9ae & 4.92 & 10.3\,h & 8/30 & baseline \\
C11t (thinking on root) & 7.67 & 15.8\,h & 12/30 & 1.56$\times$ \\
C11n (thinking, no analyzer) & 8.69 & 17.9\,h & 13/30 & 1.77$\times$ \\
C15t512 (512-token cap) & 8.97 & 18.4\,h & 13/30 & 1.82$\times$ \\
C17 (planner thinking; A40, partial 7 tasks) & -- & -- & 3/7 vs 3/7 & 1.36$\times$ vs C9e \\\bottomrule
\end{tabular}\caption{Measured scorer-hardware speed. Thinking solves $\approx$5 more tasks per 30 but is 1.4--1.8$\times$ slower.}\end{table}
Captured traffic explains why: with thinking the agent makes \emph{fewer} calls (78 vs 129 per task) and reads less prompt
(679k vs 1{,}145k tokens per task) but generates 13.5k vs 8.2k tokens per task. Reasoning is heavy-tailed (p50 39 tokens per call,
p99 1{,}974; 55 calls hold 30\% of all output), so per-call budgets barely help. Per-task time caps bound the runtime but cut the
slow tasks, which are exactly the ones thinking solves (a 5-min cap keeps 5--7 of 13 solves). Decision D28/D29: every release must be
runtime-safe; the program now targets \emph{making thinking cheap}.

\subsection{Learned graph traversal for localization}
We built \code{graph-locate}, a one-call, standard-library tool: function-level BM25 seeds, an AST call/definition graph of the
repository built at run time (organizer graphs may be empty on hidden repos), budgeted frontier expansion with a linear policy
trained by REINFORCE on nDCG@10, and a LambdaRank scorer. Held-out proxy half (78 tasks with gold functions):

the no-graph ablation matches every graph variant. With the right file in the top 10 for $\approx$94\% of tasks and 149/171 failed
runs having read the gold file, localization is not the bottleneck. Candidate C16 (C9e + tool) is queued on the held-out half.}

\subsection{Fine-tuning: external data, own data, and thinking distillation}
\begin{itemize}
\item \textbf{External trajectories} (rules allow public free data). \code{nebius/SWE-rebench-openhands-trajectories} (CC-BY-4.0,
Qwen3-Coder-480B teacher, 32{,}161 test-verified of 67k, 1{,}823 repos) and \code{nvidia/SWE-Hero} (CC-BY-4.0, 34k, 1{,}695 permissive
repos, not verified; dedup against Nebius, cap 3 per task). A converter maps OpenHands actions to our tools
(\code{execute\_bash}$\to$\code{run\_command}, \code{view}$\to$\code{read\_file}, \code{str\_replace}$\to$\code{edit\_file},
scratch files$\to$\code{/tmp}, \code{think}$\to$reasoning channel) with our exact system prompt and tools, and cuts long trajectories
into windows that mimic the scorer's history compaction (15.5k tokens per window). 45\% of resolved trajectories survive (the rest
edit test files). Competition and proxy repositories are excluded.
\item \textbf{LoRA on the frozen int4 base}: rank 128, $\alpha$=256, all linear layers; 1 epoch on 1{,}000 Nebius windows took 30\,h on
one A100 (64\,GiB peak, 60--110 tok/s; loss 0.39$\to$0.32). Its proxy evaluation (C18, adapter on C8 without a cap) is running;
an earlier attempt was invalid (served without the adapter). A Nebius + SWE-Hero mix run is training.
\item \textbf{Own trajectories}: fixing two pipeline bugs (unassigned shards; mandatory explicit \code{submit\_patch}) raised usable data
from 27 to 345 sequences (148 resolved runs).
\item \textbf{Thinking distillation (C19)}: train the fast, \emph{non-thinking} main agent on resolved \emph{thinking} runs rendered without
the reasoning (289 sequences, eval-half tasks removed), then compare C9ae+adapter vs C9ae on the 85 held-out tasks. If it works, the
model gets thinking-quality actions at non-thinking cost, the cleanest route through the runtime wall.
\end{itemize}

\subsection{What the literature suggests (research synthesis)}
\begin{itemize}
\item \textbf{SFT data}: gains scale log-linearly with trajectories and with \emph{number of repositories} (SWE-Gym: 491 trajectories
lifted a 32B model 7.0$\to$20.6; SWE-smith 5k $\to$ 40.2). Mask malformed tool-call turns, keep failed-but-informative steps masked,
curriculum by turn count (SWE-Lego: +1--2 points each); LoRA needs high rank on all linear layers (r$\geq$128).
\item \textbf{Test-time scaling}: parallel samples + execution-based selection (regression tests, then generated reproduction tests)
gives +5--15 points at N=3--16 (Agentless, Trae-Agent, R2E-Gym). Under serial scoring, intra-task parallelism (ADK
\code{ParallelAgent}) is the only way to use the nearly-free batched decode; one shared 100-call budget must be split.
\item \textbf{Localization RL} (RepoNavigator, CodeScout, ToolTrain): +2--6 resolve points at large GPU cost; not our bottleneck.
\item \textbf{Weak-model failure modes}: loops (a 10-step repeat predicts 89\% failure), tool-format errors, context overflow; prune
observations rather than summarize.
\end{itemize}

\subsection{What should be done now (prioritized)}
\begin{enumerate}
\item \textbf{Make thinking fit the budget} (largest expected gain, +0.10 or more):
 (a) finish the C17 timing; if $>$1.15$\times$, bound the planner (analyzer thinking budget 512/1024, fewer analyzer calls);
 (b) thinking distillation C19, and if it gains $\geq$+0.05 on the held-out half, scale it with more thinking captures (8--10 per
 task, train half + public tasks); (c) combine: distilled main agent + thinking planner.
\item \textbf{Fine-tuning at scale}: evaluate C18 (Nebius) and the mix; if positive, train 2--3 epochs with turn masking and
curriculum, own data 20--40\%, and speed up training (data-parallel LoRA, shorter windows).
\item \textbf{Intra-task best-of-2} (C14p, +0.26 on only 19 tasks): run full seeds; design a solver + test-writer + selector
\code{ParallelAgent} under the shared budget.
\item \textbf{Release discipline}: submit only candidates that are (i) $\geq$+0.10 on the proxy (2 seeds, paired) and (ii) runtime-safe
(same-hardware serial ratio $\leq$1.15 vs a completed submission, or main agent identical to one). Use the two final-selection slots
for the best safe candidate and the best high-upside one.
\item \textbf{Paper track} (deadline 12 November): (a) \emph{Best New Resource}: the LB-calibrated held-out proxy benchmark,
converter and forensics tooling; (b) \emph{Best Paper}: thinking under a serial budget (cost model, accuracy--time frontier,
distillation), with the budget-capped localization study and the negative RL-traversal result as supporting sections.
\end{enumerate}
