# External open datasets for SWE-agent training (trajectories and executable task sets)

Research run 2026-10-09. About 14 tool calls. Several HF cards (SWE-smith-trajectories, Skywork-SWE, Kwai-Klear, SWE-Lego, Nemotron paper) could not be fetched directly. Those facts come from search snippets and are marked "secondary".

## 1. Dataset comparison (HF id, size, license, teacher, schema, verification)

### Takeaway
The cleanest big trajectory sources are the Qwen3-Coder-480B ones (Nemotron-SWE-v1, SWE-Hero, SWE-Lego). They are permissively licensed, in OpenHands format, and close to our existing nebius data. The SERA data (ODC-By, GLM-4.6 teacher, "research and educational use") is the most legally ambiguous. For executable task sets, SWE-rebench (v1 and V2), SWE-Gym and R2E-Gym are the main ones, and all ship Docker images.

### Cited Findings
- **nvidia/Nemotron-SWE-v1**: about 59k trajectories per the card text. The viewer shows ~34.8k rows and one subset table lists 51,029 `r2e_gym` samples, so the counts are inconsistent. Issues come from SWE-Gym and R2E-Gym-Subset, with problem statements regenerated by Qwen3-Coder-480B. Teacher is Qwen3-Coder-480B-A35B-Instruct, collected with OpenHands (`execute_bash`-style function tools). License is CC BY 4.0, with some subsets BSD-3-Clause, and "ready for commercial use". The card does not mention test verification. Repo count is not stated; sample rows show pandas, Pillow, pyramid, numpy and scrapy. Size is about 11 GB. English only. — [card](https://huggingface.co/datasets/nvidia/Nemotron-SWE-v1)
- **nvidia/SWE-Hero-openhands-trajectories**: 34,269 trajectories over 11,766 unique issues. Sources are SWE-Gym, R2E-Gym-Subset and SWE-rebench. The card says it uses only MIT, Apache-2.0, BSD-2 and BSD-3 licensed repos (the card has a "BSD-2-Claude" typo). Dataset license is CC BY 4.0, commercial use allowed. Teacher is Qwen3-Coder-480B (OpenHands). Each trajectory has 49 to 201 messages. Size is 2.4 GB. The card describes no test verification. Paper: arXiv 2604.01496, "From SWE-ZERO to SWE-HERO". It describes 300k execution-free SWE-ZERO trajectories and 13k execution-backed SWE-HERO trajectories, with SWE-HERO-32B at 62.2% on SWE-bench Verified and 44.1% on SWE-bench Multilingual when trained on Python only. I did not find whether the 300k SWE-ZERO set is released. — [card](https://huggingface.co/datasets/nvidia/SWE-Hero-openhands-trajectories), [paper](https://arxiv.org/abs/2604.01496)
- **allenai/Sera-4.6-Lite-T2**: 36,083 trajectories, of which 25k were used to train SERA-32B. Teacher is GLM-4.6. It covers 121 SWE-smith codebases, so the repo count is small. Message size is about 4k to 731k characters. License is ODC-By v1.0, and the card says "for research and educational use". The card shows no tool schema; the system prompt is generic and I could not determine whether the scaffold is SWE-agent-style or OpenHands. The card says T2 patches can be compared with T1 target patches, but the authors did not use that in their main experiments. So the data is "soft-verified" at best, not test-verified. — [card](https://huggingface.co/datasets/allenai/Sera-4.6-Lite-T2), [paper](https://arxiv.org/abs/2601.20789)
- SERA mixing: 16k T2 alone scored 47.07% on SWE-bench Verified, 25k T2 scored 49.53%, and 16k T2 + 9.2k T1 scored 49.00%. SERA-32B at 32K context reached 49.5%. — [SERA paper (search snippet)](https://arxiv.org/pdf/2601.20789)
- **SWE-bench/SWE-smith-trajectories**: could not fetch the card. A secondary source (the SWE-Lego comparison table) lists SWE-smith as 128 repos, 50k task instances and 5k valid trajectories. The SWE-agent-LM-32B model card says it was trained on 5k SWE-agent + Claude 3.7 Sonnet trajectories, and the model license is Apache-2.0. The trajectory dataset license is not confirmed: the GitHub README is MIT for the toolkit, and an aggregator says CC-BY-4.0 (unreliable). Teacher is Claude 3.7 Sonnet, so Anthropic output terms may apply to that data (not verified). — [SWE-agent-LM-32B](https://huggingface.co/SWE-bench/SWE-agent-LM-32B), [SWE-smith paper](https://arxiv.org/abs/2504.21798), [SWE-Lego](https://arxiv.org/pdf/2601.01426)
- **SWE-Gym/SWE-Gym**: 2,438 instances over 11 Python repos (161 versions), MIT. Follows the SWE-bench collection procedure, with `base_commit` and `version` per instance. — [card](https://huggingface.co/datasets/SWE-Gym/SWE-Gym)
- **R2E-Gym/R2E-Gym-Subset**: 4,578 rows, Apache-2.0, 944 MB. Each row has a `docker_image` and `expected_output_json`. The preview shows only orange3. The R2E-Gym paper says the subset covers 10 repos and avoids SWE-bench repo overlap, and that SFT on it used 3,321 trajectories from 2,048 environments. — [card](https://huggingface.co/datasets/R2E-Gym/R2E-Gym-Subset), [paper](https://arxiv.org/pdf/2504.07164)
- **SWE-Lego** (arXiv 2601.01426, Jan 2026): HF ids `SWE-Lego/SWE-Lego-Real-Data` and `SWE-Lego/SWE-Lego-Synthetic-Data` (from the model card, secondary). The paper reports about 3,251 repos, 32.1k task instances, 14.1k resolved plus 4.0k "semi-resolved" trajectories. Real data is about 18.4k PR-derived instances and synthetic about 13.7k SWE-smith-style bug injections. Secondary summary: teacher is Qwen3-Coder-480B with OpenHands, 100 turns max. SWE-Lego-Qwen3-32B reaches 52.6% on SWE-bench Verified with SFT only. I could not confirm the dataset license. — [paper](https://arxiv.org/abs/2601.01426), [model card](https://huggingface.co/Lego-X/SWE-Lego-Qwen3-8B)
- **Skywork-SWE**: 10,169 Python task instances over 2,531 repos, each with a runtime image for test validation. 8,209 validated trajectories after format filtering. Skywork-SWE-32B is Apache-2.0 (the model, not the dataset), and it scores 38.0% on SWE-bench Verified. Dataset card and license not fetched. — [paper](https://arxiv.org/pdf/2506.19290)
- **Kwai-Klear/SWE-smith-mini_swe_agent_plus-trajectories-66k**: 65,994 trajectories on SWE-smith tasks, mini-swe-agent-plus scaffold, MIT (per a GitCode mirror of the card). Klear-Agent-8B scores 39.0% on SWE-bench Verified. Reported scaling is roughly linear in log(#trajectories) from 1k to 66k. The teacher model is not stated in the snippet. — [mirror](https://gitcode.com/hf_mirrors/Kwai-Klear/SWE-smith-mini_swe_agent_plus-trajectories-66k)
- **nebius/SWE-rebench** (task set): more than 21,000 issue-PR pairs, 3,400+ Python repos, CC-BY-4.0. Each instance records its source repo's license. 7,500 prebuilt Docker images are on Docker Hub, and an `install_config` field is read by a SWE-bench fork. — [card](https://huggingface.co/datasets/nebius/SWE-rebench)
- **SWE-rebench V2** (arXiv 2602.23866, ICML 2026): 32,079 tasks across 20 languages and 3,617 repos (the arXiv v1 figures; other versions differ), with prebuilt Docker images. It adds 120k+ tasks that have install instructions and fail-to-pass tests, with problem statements generated from the PR description. It includes LLM-judge quality flags. — [paper](https://arxiv.org/abs/2602.23866), [blog](https://nebius.com/blog/posts/meet-swe-rebench-v2)
- **SWE-smith generator**: toolkit that turns any GitHub repo into a Gym via bug injection; needs Docker; 128 repos, 50k instances; MIT (README). — [GitHub](https://github.com/SWE-bench/SWE-smith)
- Other 2026 papers surfaced by search (not examined): SWE-Next (arXiv 2603.20691), SWE-Master (2602.03411), SWE-TRACE (2604.14820), P2T (2605.21996), SWE-Prime (2608.27449), GAIR/OpenSWE. — see search results.

### Inferences
- Nemotron-SWE-v1 and SWE-Hero overlap heavily with each other and with the nebius set (same teacher, same SWE-Gym, R2E and SWE-rebench issue pools). Expect many duplicate instance_ids when stacking them; dedupe by instance_id/repo+base_commit first.
- Nothing here is OpenHands-to-our-tools ready. All OpenHands sets use `execute_bash`/`str_replace_editor`, which must be mapped to run_command/read_file(150-line)/edit_file/write_file/submit_patch, as already done for nebius.
- A 32B-teacher-distilled "unverified" set like Nemotron-SWE-v1 could include failed trajectories. The card gives no verification flag, so we would need to re-verify or filter by a resolved field, if present (not found).

### Gaps
- Direct cards for SWE-smith-trajectories, Skywork-SWE, Kwai-Klear, SWE-Lego: not fetched (domain check failed in some calls); license, token lengths and exact HF ids are unconfirmed there.
- Per-trajectory token or turn statistics: only SWE-Hero (49 to 201 messages) given. Nemotron-SWE-v1 and Sera: no.
- Repo counts for Nemotron-SWE-v1 and SWE-Hero: not stated.
- SERA scaffold, and the "newer than Sera-4.6-Lite-T2" releases: not found. SERA's CC BY 4.0 is the paper's; the data card is ODC-By "research and educational use".

## 2. Executable task sets we could roll out on (rejection sampling / RL) and offline setup difficulty

### Takeaway
SWE-rebench (v1 and V2), SWE-Gym, R2E-Gym, Skywork-SWE and SWE-smith all provide Docker images or Docker-based setup. None is described as runnable without Docker. Offline subprocess use means pre-extracting the repo checkout plus the Python env from the images ahead of time.

### Cited Findings
- SWE-rebench: Docker Hub images (7,500 prebuilt) plus `install_config` (requirements, environment, version) per task. — [card](https://huggingface.co/datasets/nebius/SWE-rebench)
- SWE-rebench V2: prebuilt image per task, setup via an interactive agent that resolves dependencies. — [paper](https://arxiv.org/abs/2602.23866)
- R2E-Gym-Subset: `docker_image` per row (e.g., `namanjain12/orange3_final:<hash>`). — [card](https://huggingface.co/datasets/R2E-Gym/R2E-Gym-Subset)
- SWE-smith: Docker is required for execution environments. — [search result](https://github.com/SWE-bench/SWE-smith)
- Skywork-SWE: a runtime-environment image per instance. — [paper](https://arxiv.org/pdf/2506.19290)
- SWE-Gym: only `base_commit`/`version` on the card; environments follow SWE-bench. — [card](https://huggingface.co/datasets/SWE-Gym/SWE-Gym)

### Inferences
- Easiest offline path: use the install_config of SWE-rebench Python tasks to build venvs on a machine with internet, then ship a tarball per repo (venv + checkout at base_commit) to the offline cluster. Docker image layers can alternatively be exported (`docker save`) and unpacked as rootfs/venv files, but this needs a machine with Docker.
- SWE-smith bug-injection tasks on few repos (121 to 128) are cheap to set up (a repo's environment is shared across many tasks), so best per-GB-of-setup yield. Per-repo env sharing also applies to SWE-Gym (11 repos).
- SWE-rebench has the most repos (3,400+), so most diversity, but per-repo setup cost scales with repo count.

### Gaps
- No source found that describes a Docker-free or subprocess-sandbox run of any of these. Setup difficulty estimates above are my inference.

## 3. Mixing ratios, dedup/decontamination, diversity

### Takeaway
No controlled study of external versus own on-policy ratio for SWE agents was found. Closest evidence: SERA's T1+T2 mix, SWE-smith's per-instance cap, and repo-overlap exclusion in R2E-Gym.

### Cited Findings
- SERA: 16k T2 + 9.2k T1 (49.00%) is close to 25k T2 (49.53%) and clearly above 16k T2 (47.07%). — [SERA](https://arxiv.org/pdf/2601.20789)
- SWE-smith limits any task instance to 3 trajectories because repeatedly-solved "easy" instances were found to degrade the model. — [search snippet citing SWE-smith](https://arxiv.org/pdf/2504.21798)
- R2E-Gym used only repos with no overlap with SWE-bench. — [R2E-Gym](https://arxiv.org/pdf/2504.07164)
- SWE-TRACE: shortest-path (cascaded) traces beat raw successful rollouts: 4B 33.6% to 37.8%, 30B 56.4% to 59.2%. — [SWE-TRACE](https://arxiv.org/pdf/2604.14820)
- P2T: 1.8k curated SWE-Gym trajectories improved Pass@1 by up to +10.8 points over outcome-filtered SFT. — [P2T](https://arxiv.org/pdf/2605.21996)
- Kwai-Klear: SWE-bench Verified rises roughly linearly with log(#trajectories), 1k to 66k. — [mirror](https://gitcode.com/hf_mirrors/Kwai-Klear/SWE-smith-mini_swe_agent_plus-trajectories-66k)
- SWE-bench-style decontamination in the datasets above is mostly by repo exclusion or by using non-overlapping sources (R2E). I did not find SWE-rebench's or Nemotron's explicit decontamination procedures.

### Inferences
- Reasonable starting hypothesis (not evidence-backed): treat external data as the base for tool-use format and breadth, and rely on own-agent-verified rollouts for the final stage; cap per-instance trajectories at about 3; dedupe on instance_id across sources; drop any repo that appears in hidden-test-like benchmarks.
- Our hidden test includes private repos, so repo-count diversity (SWE-rebench, Skywork-SWE, SWE-Lego real) likely matters more than raw volume. This is an inference; no repo-scaling ablation was found.

### Gaps
- No direct on-policy vs distilled mixing-ratio study found; no isolated repo-count scaling study found.
- SWE-bench decontamination status of Nemotron-SWE-v1 / SWE-Hero (SWE-Gym and R2E repos overlap some SWE-bench repos, e.g., pandas, numpy are in SWE-Gym; SWE-bench Verified is Django/sympy-heavy): not verified.

## 5. License cleanliness ranking (for OSI-open-source winners)

### Takeaway
Ranked by what I verified. "Output-use" terms of the teacher matter: Qwen3-Coder-480B is Apache-2.0 (my knowledge, not re-verified here); GLM-4.6 license not checked; Claude 3.7 outputs are governed by Anthropic terms.

### Cited Findings
1. SWE-Gym (MIT) — [card](https://huggingface.co/datasets/SWE-Gym/SWE-Gym); R2E-Gym-Subset (Apache-2.0) — [card](https://huggingface.co/datasets/R2E-Gym/R2E-Gym-Subset). Task sets, no teacher outputs.
2. nvidia/SWE-Hero (CC BY 4.0, only MIT/Apache/BSD repos, commercial OK) and Nemotron-SWE-v1 (CC BY 4.0, some BSD-3, "ready for commercial use") — cards above. The SWE-Hero repo-license filter makes it the cleanest trajectory set.
3. nebius SWE-rebench task set (CC-BY-4.0, but per-repo licenses vary and must be respected) — [card](https://huggingface.co/datasets/nebius/SWE-rebench). Same applies to our existing nebius trajectories.
4. Kwai-Klear 66k (MIT per mirror; underlying SWE-smith repos' licenses and the teacher are unconfirmed).
5. SERA (ODC-By v1.0, "research and educational use" wording) — [card](https://huggingface.co/datasets/allenai/Sera-4.6-Lite-T2). Wording is ambiguous for a competition that requires open release; GLM-4.6 teacher terms unchecked. Use last.
6. SWE-smith-trajectories (Claude 3.7 teacher; dataset license unconfirmed) — lowest confidence.
Unverified: SWE-Lego, Skywork-SWE dataset licenses.

### Inferences
- OSI note: CC BY 4.0 / ODC-By are data licenses, not OSI software licenses; the competition rule most likely concerns released code/models, but this should be confirmed with the rules.

### Gaps
- Qwen3-Coder and GLM-4.6 output-use terms were not fetched in this run; confirm from their model cards.

## Ranked recommendation (for Gemma-4-31B LoRA, Python, own tools)
1. **nvidia/SWE-Hero-openhands-trajectories**: cleanest license, 34k trajectories, 11.8k issues, same teacher family as the nebius data; first add after dedupe.
2. **SWE-Lego Real-Data** (after confirming license): the most repos (~3k) and "resolved" split; best match for private-repo robustness.
3. **nebius/SWE-rebench (V1/V2) task set**: the executable set for own-agent rejection sampling, with the most Python repos; grep for google/* repos.
4. **R2E-Gym-Subset and SWE-Gym**: small, cleanly licensed, Docker images or SWE-bench-style envs; good for cheap RL/rejection sampling.
5. **SWE-smith generator**: if absl/gin/jax tasks are needed, generate them from those repos; also provides cheap shared-env tasks.
6. **Nemotron-SWE-v1**: large but overlaps SWE-Hero and no verification statement; sample after dedupe.
7. **Kwai-Klear 66k, Skywork-SWE, SERA, SWE-smith-trajectories**: lower priority, scaffold mismatch (mini-swe-agent-plus, SWE-agent) or license ambiguity.
